# SEA-PINN Reproducibility Code

## Scope of This Release

The manuscript reports experiments on 20 PDE benchmark problems. This code
package provides three representative executable examples:

- Case 5: `Poisson2D_ManyArea`, evaluated against a high-fidelity numerical
  reference solution.
- Case 7: `Heat2D_Multiscale`, evaluated against an analytical solution.
- Case 11: `NS2D_BackStep`, evaluated against a high-fidelity numerical
  reference solution.

These three cases are included to demonstrate the evaluation protocols used
in the manuscript and to provide a compact, directly runnable reproducibility
package. The SEA-PINN architecture implementation is independent of the
selected PDE case.

The full raw data and complete experimental results used in the manuscript are
provided separately, as described in the Data Availability Statement.

This package provides two executable experiments. Experiment 1 computes
step-0 initial-loss distributions over 1000 initialization seeds and
tenth-iteration loss-variance statistics. Experiment 2 trains representative
PINN runs and reports relative L2 errors, training-loss comparisons, and
solution heatmaps.

## Environment

Recommended environment:

```powershell
conda create -n seapinn-code python=3.9
conda activate seapinn-code
```

Install PyTorch first. Choose one command according to the machine:

CPU-only PyTorch:

```powershell
pip install torch==2.0.0 --index-url https://download.pytorch.org/whl/cpu
```

NVIDIA GPU PyTorch with CUDA 11.7:

```powershell
pip install torch==2.0.0 --index-url https://download.pytorch.org/whl/cu117
```

Then install the remaining dependencies:

```powershell
pip install -r requirements.txt
```

The package includes the DeepXDE-compatible runtime used by these scripts, so
no separate DeepXDE installation is required.

By default, the scripts use `--device auto`: they use CUDA if the installed
PyTorch build can see a GPU, otherwise they run on CPU. Use `--device cpu` only
when CPU execution is desired explicitly.

## Network and Optimizer Settings

All three models use the same depth and width in these representative examples:

- layer sizes: `[input_dim] + [32] * 9 + [output_dim]`
- hidden layers: 9
- hidden width: 32
- weight initializer: uniform
- bias initializer: zeros
- optimizer: Adam
- learning rate: `1e-3`
- Experiment 1 default iterations: 10
- Experiment 2 default iterations: 5000
- loss weights: all `1.0`

`FNN-PINN` uses the standard fully connected DeepXDE FNN with SiLU activation.
`SEA-PINN` uses the same SiLU backbone and adds neuron-wise self-adaptive
weights generated by `Linear(32, 8) -> Tanh -> Linear(8, 32) -> Sigmoid` after
each hidden layer. `TSA-PINN` is optional; it uses sine/cosine hidden transforms
with trainable frequency parameters initialized to `1.0`.


## Experiment 1: Initial-Loss Distribution

This experiment computes initial total training-loss distributions for cases
5, 7, and 11 using the shipped Hammersley training sample files. The default run uses
`FNN-PINN`, `SEA-PINN`, and `TSA-PINN` with initialization seeds `1-1000`. The
training coordinates are unchanged across seeds; the seeds control the
neural-network parameter initialization.

The violin plot uses the first recorded training loss at step 0, before any
optimizer update is applied. The default run uses `--iterations 10`, and the
variance bar plot is computed from the total training loss recorded at step 10.

Default 1000-seed run:

```powershell
python run_initial_loss.py
```

Per-run training logs are not saved by default, because the full default run
would otherwise create one log file for every case/model/seed combination. To
save these logs for debugging, add `--save-logs`.

## Experiment 2: Representative Accuracy

This experiment trains representative runs on cases 5, 7, and 11, then reports
the relative L2 error and generates loss curves and solution heatmaps. It compares
`FNN-PINN` and `SEA-PINN` by default. `TSA-PINN` is available as an optional
baseline.

The run loads the shipped Hammersley sample files directly. By default, the
network initialization seed is set to `42`. The loaded sample coordinates do not change when
`--init-seed` is changed.

Default run:

```powershell
python run_representative_accuracy.py --models FNN-PINN SEA-PINN
```

Include TSA-PINN:

```powershell
python run_representative_accuracy.py --models FNN-PINN SEA-PINN TSA-PINN
```

Use another initialization seed:

```powershell
python run_representative_accuracy.py --models FNN-PINN SEA-PINN --init-seed 7
```

Quick test:

```powershell
python run_representative_accuracy.py --quick --device cpu
```

The training loss is saved during optimization, and the relative L2 error is
computed once after training on the evaluation data.

For Experiment 1, `initial_loss_violin_case5_case7_case11.*` uses the step-0 total
training loss, while `initial_loss_variance_statistics.csv` and
`initial_loss_variance_bar.*` use the total training loss recorded at step 10.

`outputs/representative_accuracy/summary.csv` records the case, model,
initialization seed, iterations, requested device mode, relative L2 error,
maximum absolute error, and runtime.

## Sample and Reference Data

The sample and evaluation data files are:

- `data/samples/case5_train_samples.npz`: case 5 training collocation
  arrays.
- `data/reference/poisson_manyarea.dat`: case 5 high-fidelity numerical
  reference solution.
- `data/reference/poisson_a_coef.dat` and
  `data/reference/poisson_f_coef.dat`: case 5 piecewise coefficients.
- `data/samples/case7_train_samples.npz`: case 7 training collocation
  arrays.
- `data/samples/case7_eval_samples.npz`: case 7 evaluation data from the
  analytical solution.
- `data/samples/case11_train_samples.npz`: case 11 training collocation
  arrays.
- `data/reference/ns_0_obstacle.dat`: case 11 high-fidelity numerical
  reference solution.

The high-fidelity numerical reference data files for Case 5
(`Poisson2D_ManyArea`) and Case 11 (`NS2D_BackStep`) are provided by the
PINNacle benchmark.

The example scripts load these pre-generated files directly. This keeps the
loss curves, relative L2 errors, and heatmaps tied to the same well-covered
Hammersley collocation and evaluation data.

Cases 5 and 11 are evaluated using all rows in their numerical reference data.
Case 7 is evaluated on the fixed evaluation points stored in
`case7_eval_samples.npz`; heatmaps are generated at `t = 0.1`.

The data were produced or selected with the following counts:

- Case 5 training: `domain=8192`, `boundary=2048`.
- Case 5 testing: all rows in `data/reference/poisson_manyarea.dat`.
- Case 7 training: `domain=8192`, `boundary=2048`, `initial=2048`.
- Case 7 testing: `domain=8192*4`, `boundary=2048*4`, `initial=2048*4`.
- Case 11 training: `domain=8192`, `boundary=2048`.
- Case 11 testing: all rows in `data/reference/ns_0_obstacle.dat`.

For case 11, `boundary=2048` is the DeepXDE `num_boundary` sampling parameter
before boundary-condition expansion. DeepXDE filters the sampled boundary set
for each boundary condition and concatenates the per-condition collocation
arrays into `train_x_bc`. Therefore, the stored `train_x_bc` row count equals
`sum(num_bcs)` and can be larger than 2048.

The training sample files include the collocation arrays used internally by
DeepXDE. The evaluation data are used only for the reported relative L2 errors
and heatmaps.
